# Unchanged arsenal reads preserve coherent construction quotes

A shared arsenal read currently forwards its economy unconditionally. The common economy setter
marks construction quotes stale and rereads the island even when the read adds no arsenal or money
facts. A quiet defended-island refresh can therefore read coherent offers, then immediately disable
them while an unnecessary second read is pending.

Suppress only that redundant READ projection callback. Require a previously accepted same-origin
arsenal view with identical revision and domain content, and require incoming money to exactly match
the CURRENT canonical origin, revision and all treasury fields. The previous arsenal envelope may
be older after a legitimate construction; it must not replace the current money comparison. Initial
reads, changed inventory/revision/funds, conflicts and every write (including free equip/return and
confirmed replay) keep existing callbacks and refusal behavior.

Keep every actual HTTP read, read ticket, context fence, inventory adoption and display update.
Do not relax construction quote freshness, the shared economy setter or unknown/legacy context
gates. The bounded change belongs in the arsenal controller; it adds no treasury store or authority.

Verify duplicate and canonically redundant reads, changed domain/funds and all write paths. Exercise
the actual island/API/DOM chain with a delayed extra reload: one legitimate quiet island read plus an
unchanged arsenal read must leave the accepted construction offer usable and permit one ordinary
pointer build. The transport is synthetic; provider gameplay remains separate acceptance.

The regression first failed two unit cases and the real-DOM case. The actual island/API chain
read a valid available quote, then performed an unnecessary second core read, marked the offer
stale, disabled its button and submitted no build through an ordinary pointer action. After the
bounded READ-only correction, all 69 cases across six focused arsenal, context, DOM and wallet
ordering files passed in 11.83 seconds. The same component now retains one quiet core read and
one arsenal read, a usable current offer and one client construction submission. Changed facts
and all buy/equip/return/replay callbacks remain covered. Normal build passed in 1.42 seconds,
spoiler guard passed (257 text files, 12 protected lines), and whitespace review was clean.
Independent source review found no actionable issue. No provider or candidate was changed;
rendered provider acceptance remains separate.
