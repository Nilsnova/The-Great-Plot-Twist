# Wall Gameplay: contract and execution detail

[Wall epic #241](https://github.com/Nilsnova/The-Great-Plot-Twist/issues/241) contains 24 bounded proposed tasks. The existing five wall levels and hostile blocking already work; the missing behavior is arbitrary approved placement, truthful persistence, complete transactions and the coordinated visual/playable result.

## First release and selected extras

Start with the existing twelve stable IDs and single-wall upgrades. WALL-01 records actual actor/geometry/coastal/reservation/version rules. WALL-02 records the allowance and all supported identity sources. WALL-13 then proves continuous shape/clearance agreement; 06/07/08 admit, preserve and preview the selected free-grid rule.

Larger capacity is optional for the first release, but required before any larger claimed target arrangement is offered. Its five exclusive slices are 03 catalogue/complete reads; 19 table CHECK admission; 22 current manifests/health vectors/first-new-position handling; 20 the isolated paid-repair guard; 21 demolition/refund guards. The old 30-layout-row, 50-building-row and 26-health-vector assumptions must cover the whole selected island, not just walls. Do not copy build/upgrade/move/reset functions that need no behavior change merely to widen an ID list.

The paid-repair function is already 356 lines before focused tests, so it is isolated. Demolition quote/commit are 68+185 lines and remain a separate bounded review. No fragile SQL text rewriting, production apply or flag activation is authorized.

Batch upgrading 09/10/11 is an optional selected-set convenience using existing prices/health/unlocks. A batch cannot silently skip an ineligible wall or round one discounted aggregate instead of summing real per-piece rounded prices. Legacy and V1 eligibility remain distinct. Existing single Upgrade does not wait for this route.

## Critical state and payment rules

A trusted persisted rule/allowance carrier is distinct from existing LayoutInfo.version 1/2, RecoveryVersion and WaveProtocol. A request may check an expected version but cannot grant itself permissive placement. A read cannot normalize a newly accepted wall back to an old lane. Old effective positions and paid value have an explicit transition policy.

Canonical construction retains ID-position pairing, bounded grid cells and exact unlocked/unbuilt IDs. One batch receipt needs distinct per-piece refs/instances/contributions under actual UNIQUE and 64/120 reference bounds. Permission precedes private receipt replay. A lost reply is reconciled with the original UID; closing the UI does not reverse a committed action. A reset/demolition/rebuild never causes an old receipt to reconstruct, heal or refund a new instance.

Settle legitimate earned recovery at a controlled database instant under old coordinates/rates, then change future policy. A refused action may materialize ordinary elapsed recovery; it grants no action-induced heal, level, purchase or payment. Moving across a Workshop radius cannot retroactively earn the new rate. V1 damaged-upgrade rules are not silently imposed on legacy behavior.

## Combat and display

Normal boarder entry cannot cross a standing wall. Existing already-inside egress after a restored footprint is an explicit exception. Captain, ship and projectile behavior is the approved actor matrix, not an art inference. Equal-budget gap/compartment/mixed-level/irrelevant-wall fixtures show actual tradeoffs; not every legal isolated wall is guaranteed useful or attacked.

WALL-23 is the missing live combat connection layer. VIS-14 owns its material family, not a second barrier simulation. Real zero health opens the displayed and actual breach; accepted positive repair restores only the correct instance/state. The guide-cache durability finding is first reproduced in WALL-16; source inspection alone is not a passing bug reproduction.
