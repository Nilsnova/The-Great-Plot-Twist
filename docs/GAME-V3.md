# The Great Plot Twist, v3: one island, one crew, a narrated campaign

> **What this file is:** the owner's direction after playing with his brother on Wed 11 Nov (late evening), and the binding contract for the v3 builds. [TOWER-DEFENSE.md](TOWER-DEFENSE.md) stays valid for everything this file does not change. A build that must deviate changes this file in the same commit and says so in its report.
>
> **Decisions by the owner (11 Nov):** clean cartoon 2D art (not pixel art); one island per game, the Harbor and the rest become buildings on it; every player keeps their own coins and builds on the shared island; the narrator is voiced (ElevenLabs, the existing key and plan, no new spending).

## 1. The game in one paragraph

You open the game and **create a game** (a room) or **join** one with its code. Up to **10 players** play on **one shared island**. When everyone is in the lobby, the host presses **Start**. A voiced **narrator** tells the story and introduces every new thing as it arrives, so nothing is overwhelming. The crew defends the island against **100 waves** of pirates; each wave brings something new in the first rounds, then the advancement deepens: tower skill trees, a technology hub, a repaired ship that lets the crew sail out to fight at sea, close combat on the beach. You can **pause** between waves, **leave**, and any member can **continue** the same game later: the island, its buildings and the wave reached are saved.

## 2. Rooms (lane R)

- **Front door:** Play → **Create a game** · **Join a game** (type or paste a code, or open a link `?game=ISLE-XXXXX`) · **Continue** (the games you are a member of, newest first, with wave reached and who is in it).
- **A game is an island.** Creating one makes an island with a code (today's `ISLE-XXXXX`) whose creator is the **host**. Members: 1 to 10 (the creator plus up to 9). Joining a game makes you a member for good (until you leave it in the Menu). Guests (anonymous sign-in) join with the code as today.
- **Lobby:** the island in the background, a card with the code, the invite link and QR, the list of members online (name tags), and **Start** (host only; any member if the host is away for 60 s). The narrator's opening plays when the host presses Start the first time.
- **Pause / leave / continue:** between waves the host (or any member when the host is away) can **Pause** (no auto next wave, the break stays open until Resume). Leaving a running wave counts you out of that wave. Any member can open the game from **Continue** and ring the next wave, alone or with others. Progress belongs to the island: buildings, wave reached, unlocks, research.
- **One island only:** no sea chart; the Harbor (market calls, football board) and the other services are buildings on the island that unlock by wave (section 4). Pirate Point and the separate islands leave the game (the three lamps can return later as a boss-wave mechanic on the island).
- **Coins:** each player's own wallet (as today). Everyone builds and upgrades on the island with their own coins; loot is paid to each participant of a won wave.
- Membership is the rule on a game's island: build, upgrade, the bell, `POST /api/waves/join` of its waves and `GET /api/island/visit/{code}` answer 403 `not_member` to a non-member (the host always in); a guest refused with 409 `game_full` is not admitted by the guest gate.
- Live rooms: the island room `live:place:isle_<code>:1` carries up to 10 players (raise MAX_PLAYERS and every filter that assumes 4).

### 2.1 How it is built (lane R, `feat/v3-rooms`)

- **Data model: a game is an island.** Every player keeps exactly one island (`islands`, one row per player, made by `island_open`); that island is the game the player **hosts**, and its code is the game's code. A player can be a **member** of any number of other players' games: `island_members (island_owner, player_id, role host|member, joined_at, opened_at, left_at)` in `supabase/migrations/20261112040000_game_rooms.sql` (RLS on, no policy, server only). Existing progress stays where it is and becomes each player's first game; the migration backfills every host row and makes tonight's friends (anyone who fought a wave on somebody else's island, the 9 most recent per island) members, so they find the game under Continue. One island per player means **Create** opens your own island (it answers the game you already host); a second game of your own would need islands keyed by game, which is not needed for v3.
- **The 10-player door** is SQL: `game_join()` locks the island row (the lock `wave_start()` takes too), counts the active members (the host counted once) and refuses `game_full` at 10. A member coming back is not new; one who left counts again. `game_leave()` refuses the host. `game_list()` (Continue, newest first by `opened_at`) and `game_members()` (the lobby) only read. All four are `security invoker`, `search_path ''`, executable by `service_role` only.
- **Routes** (`backend/server/routes/games.py`): `POST /api/games` (your game; `created` says whether the island was made now), `POST /api/games/join {code, actionUid}` (admits a guest like the class code; `409 game_full` "This game has 10 players already"; a code you are not in spends the player's code budget, a code that names no game also the address's), `GET /api/games` (Continue), `GET /api/games/{code}` (the lobby: members with `id`, `name`, `role`, `you`; `403 not_member`), `POST /api/games/leave {code}` (`409 host_cannot_leave`). `POST /api/island/invite/join` is an alias of join. **Membership is the rule** on a game's island: build, upgrade (with `code`) and the bell (`where` = a code) answer `403 not_member` to a player who is not in that game.
- **Who is online** is not stored: it is the presence of the island room (its ids are the lobby's ids). Without a live presence (`?islands=fake`) a small `game_hello {who}` heartbeat stands in (every 20 s, plus one hello back to a newcomer).
- **Start and Pause** are room messages (`src/island/game-room.js`, checked field by field in `src/net/live-rules.js`): `game_state {who, started, paused, first}`, sent on Start and on Pause/Resume and once as the answer to a newcomer's hello, so a friend who arrives later learns that the game is on (their lobby closes) or paused. Start emits `bus.emit({type: 'game_started', first})` on every page (`first`: the game never won a wave and this device never started it). Pause holds the break open (no Auto next, "Next wave" waits) and the break card says "Paused by <name>". Only the host may Start or Pause, any member once the host has been away for 60 s. Names never travel in messages; they come from the lobby answer.
- **Front door:** Play shows the games card (after the first-run lore and pages): Continue (code, host, wave, players), Create a game, Join a game (ISLE-XXXXX or the 5 symbols). A `?game=ISLE-XXXXX` link (`?visit=` still works) goes straight in through the friend's landing. After Create, Join or Continue the lobby opens over the island: the code, Copy link and QR, the players with who is online, Start. The Menu has Players and invite (the lobby) and, in a friend's game, Leave this game.
- **One island:** behind `one_island` (`src/island/one-island.js`), ON by default in code: the Sea chart leaves the Menu, M and the gamepad, the Menu's Harbor card and "Join the class harbor" go too (Menu entries marked `travel`), and the goals "Sail to the Harbor" and "Place a stake" become "Build a wall" and "Win wave 3" (same places in the list). In a friend's game the chip at the top left says **Nils's game · ISLE-K7Q2M** with **Players** (the lobby) instead of "Visiting Nils's island · Sail home" (`visitChip`), since a game is shared and there is no home to sail to. `/api/config` may send `flags.one_island = false`, or `?oneisland=0` for one tab, to bring travel back; the old code stays. Class-code players and the islands-off game keep travel.
- **Budget for 10:** a wave room of n players costs n x (n - 1) deliveries per round of sends; `waveGapMs(n)` keeps a room under 90 deliveries a second (200 ms up to 4 players, 1 s at 10). Moves keep their own budget (`sendGapMs`).

## 3. Combat (lanes C and S)

- **Pirates come ashore** (boarding, close combat, a ring of inner walls, rebuilding broken walls): being built on `feat/td4-boarding`, see TOWER-DEFENSE.md §12.
- **The heart of the island:** the lighthouse/treasure in the middle. Boarders that are not fighting a player go for it; when its ♥ reaches 0 the wave is lost **for everyone**.
- **Players have health.** Each captain has hp (shown as a small bar over every character; your own also in the HUD). Boarders within reach attack the nearest captain. At 0 hp a captain **falls**: they cannot act, a ring and a timer show over them. A teammate who stands next to them and holds E for 2 s **revives** them for coins (🪙 20 + 5 per wave, paid by the reviver; the server checks and charges like any spend). A fallen captain not revived stands up by themselves at the next break. If every captain on the island has fallen, the wave is lost.
- **Built (lane H, `feat/v3-health`): captain health.** The numbers live in `CONFIG.health` of `frontend/src/pirates/sim.js`, the price also in `backend/content/islands.json` (`revive`; a test keeps them equal).
  - **In the sim, from synced inputs.** Every screen runs the same sim, so hp, falls and revives are sim state: each player's controller sends where their captain stands (`captain_move {x, z, colour?, away?}`) when it moved (every 0.5 s, or 2 × the room's wave gap with more players) and at least every 3 s, stamped a little further ahead than a shot so it still reaches every screen before its tick. The first position puts the captain in the wave with **100 hp**; `away: true` (another place on screen) or 8 s without a word takes them out (not a target, not counted). Shots and blows of a known captain also say where they stand.
  - **Boarders.** A boarder within **3 units** of a standing captain goes for the nearest one (ties: the lower id; at most **3 boarders on one captain**, the rest walk on to the heart), strikes from 1 unit **4 hp a second** (× the wave's damage curve, so from wave 10 on more) and lets go when the captain is more than 5 units away; then it walks its route again (`pickBoarderTarget`, TOWER-DEFENSE.md §12).
  - **Falling.** At 0 hp the captain **falls**: no walking (game.js holds the player), no shooting, no cutlass, no building or repairing; a fallen captain's shots and blows do nothing in the sim either. They lie in their lobby colour (`captain-down-1…10`, `src/art/people.js`) inside a pulsing red ring with a timer over them (minutes:seconds down), and their standing presence figure hides meanwhile (`src/pirates/figures.js` matches the sim's captains to the figures by lobby colour, near where the sim has them; a standing teammate's hp bar sits over their figure); your own screen shows a slim strip inside the wave bar, **You have fallen · a teammate can hold E next to you · 0:12**, so the fight stays in view, and your hp shows under the wave bar (`Captain 72 / 100`) with a bar over every captain's head.
  - **Help up for coins.** Next to a fallen teammate (2.2 units) the prompt says **Hold to help up · 🪙 35** (wave 3); holding E or the prompt fills it in **2 s** (the ring around them fills with gold dots), then `POST /api/waves/revive {waveId, fallen, downAt, actionUid}` charges the helper **🪙 20 + 5 × wave** (`wave_revive()`, migration `20261112050000_captain_revive.sql`: the wallet locked first, reason `captain_revive`, ref `revive:<actionUid>`, only a member of the game who is in that wave and has not finished it, while it runs; the database takes the wave number itself). `downAt` is the sim tick of the fall, the same on every screen: one fall is paid for once (a unique index on `captain_revives (wave_id, fallen, down_at)`), so when two teammates finish the hold on the same captain together the first pays and the second is refused `409 already_up` ("Already up: a teammate helped them first.") and pays nothing. Only then does the revive go to the room (`captain_revive {targetId, x, z}`), and every sim stands the captain up with **50 hp**. Letting go before 2 s pays nothing; a refusal (too few coins) shows its words on the prompt, and you let go before trying again. The fake server (`?islands=fake`) has the same route.
  - **Not helped up:** a fallen captain stands up at the next break (every wave starts everybody at full hp). **Every captain on the island down:** the wave is lost (`wave_ended` reason `captains_fallen`; the banner says "Every captain fell."). Alone, your fall is that.
  - **Narrator:** `player_fell {playerId, self}`, `player_revived {playerId, self, by}` and `captains_all_fallen {}` on the bus (only what happens now, not a late joiner's catching up); the five lines were already in `lines.json`.
  - **Balance (8 seeds each, `tests/pirates/health.test.js`).** A captain who fights (the cutlass at the nearest boarder within reach) never fell in waves 1 to 3, with nothing built, one cannon, or one cannon and the inner ring, at the heart or on the east beach (the test keeps it so); at the wave-5 boss with the `boss5` island and at wave 10 with `mid`, none either. A captain who only stands there does fall: at the heart with nothing built every time (from wave 2 that wave is lost anyway), on the east beach where the boarders land 2 of 8 at wave 1 with nothing built, 1 of 8 at wave 3 with one cannon, 5 of 8 with one cannon and the ring, 1 of 8 with two cannons and the ring.
  - **Checked in the browser** (`npm run test:mp`): in the first wave the friend stands on the boarders until he falls, the owner walks up, a short hold pays nothing, a full hold pays 20 + 5 × wave, and both pages see the fall and the revive at the same tick.
- **The wave bar** stays at the top (wave · ships left · ♥ of the heart); individual bars above characters.
- **Weapons and skills:** the captain's skill tree and weapon shop are being built on `feat/td4-skills`.

### 4.1 How it is built (lane P, `feat/v3-campaign`)

### 4.2 Tearing a building down (lane T13, `feat/v3-demolish`; the owner's decision of 12 Nov)

- **Who and when.** Any member of the game (the host or a player who joined and has not left) may tear down a wall, cannon, mortar, watchtower or house on the game's island, **only between waves** (no wave running there, its countdown included: `409 wave_running`). Never torn down: the heart of the island (the cabin), the harbor bell, the Harbor, the Tech hub and the wreck (`409 protected`), the home islet's buildings (the signal station the finale counts on among them) and Pirate Point's buildings. The building's tower skill goes with it.
- **Coins back.** Every player who paid for the building gets back **half of what they themselves paid for it** (the build and every level they paid for), rounded down, into their own wallet (reason `building_refund`, ledger ref `demolish:<actionUid>`). Nobody gets a teammate's coins. A level without a payment row (the host's own builds, and every building from before the migration) counts as paid by the host at its catalogue price: a legacy level-3 cannon gives the host back half of 🪙 30 + 60 + 120 = 🪙 105. A payer whose account was deleted gets nothing, and their share goes to nobody.
- **The card.** A built building's card has a secondary red-outlined **Tear down** button (never the focus the card opens with; off with "You can tear it down between waves." while a wave runs). It opens a confirmation with the server's own quote: "Tear down this Cannon (level 3)? You get back 🪙 X. Ana gets back 🪙 Y." with **Keep it** (the focus) and a red **Tear down**. After it, the spot is empty on every screen at once (the room's `island_changed`, the co-op build path), and anything open in the campaign can be built there. The other payers who are online get a toast: "Nils tore down the Cannon. You got back 🪙 Y."
- **Routes.** `GET /api/island/demolish?spot=&code=` (the quote, changes nothing) and `POST /api/island/demolish {spot, actionUid, code?}` (the island and `demolished: {spot, kind, name, level, refunds: [{id, name, coins, you}], repeat}`); the fake (`src/pirates/fake-api.js`) answers the same.
- **Database.** `supabase/migrations/20261112080000_demolish.sql` (applied by the owner only): `building_payments` (one row per paid level of one building, keyed by its `islet_buildings.ref`, so a building rebuilt on the same spot starts with no payments), written by `island_build()` and `island_upgrade()` from now on (each word for word as before plus that one insert); `building_demolitions` (one row per tear-down: a repeated click pays nothing twice); `island_refund_split()`, `island_demolish_quote()` and `island_demolish()`. ### 4.3 Wave events (T17, `feat/v3-waves`)

- **One event a wave from wave 3**, chosen from the wave's seed and number (`frontend/src/pirates/wave-events.js` `eventFor`, repeated step for step by `backend/server/island/wave_events.py`; the table is `backend/content/wave_events.json` with a browser copy, and both languages check its samples). A bonus the wave does not allow is dropped, never refused. No migration: the bonus rides on `p_loot_base` of `wave_finish()`.

### 4.4 Boss finishers (T18, `feat/v3-waves`)

- **First-time practice (T28):** before scoring, explain each task and offer Practice or Skip practice per player, island and task kind, in solo and multiplayer. Practice is personal and cannot change the crew score or rewards. The real attempt keeps its shared target. Standing participants announce readiness; the scored clock waits for everyone, up to a visible 60-second maximum. Guidance is remembered locally after finishing/skipping, not after interruption or timeout. See [D038](DECISIONS.md#d038--personal-boss-practice-before-the-shared-attempt--2026-11-14), [contract](INTERFACES.md#t28-boss-minigame-preparation) and [evidence](evidence/T28/README.md). Implementation is in PR #19, not a claim about the deployed game.

- **Trigger:** a boss (a boss warship or dreadnought, Redtide's own ship) hit below 25% of its hull while a captain stands in the wave is held at 1 hp; at the end of that tick the battle freezes (the sim's clock stands still; only positions and finisher input count) and a finisher starts for every standing captain in the wave. One per wave for the regular bosses, plus Redtide's. Fallen captains and captains not in the wave watch.
- **The task** (`frontend/src/pirates/finisher/`): haul the chain (waves 5 and 10: hold to lift a needle, keep it in a moving zone 60% of 10 s), aim the great cannon (15 to 25: 7 hits on a moving weak spot in 10 s, a 0.5 s reload), board and duel (30+: press the arrow shown, 55% of the prompts net of mistakes), Redtide at wave 100: all three in a row, 8 s each, two of three win. The goal grows with the captains present, a little less than in proportion (ten captains need 20% less each), so one captain can win alone. Settings › **Easier finishers** widens the zone and the weak spot and slows the prompts for that player.
- **Sync:** every 100 ms of the finisher is a sample; each player sends their samples in windows (`finisher_input {from, marks, easy?}`, at most 24 marks, one message per max(500 ms, 2 × the room's wave gap)), checked in `sync.js` and `live-rules.js`. The score depends only on the set of samples heard, never on when they arrived, and a grace time after the task lets the last windows arrive, so every screen decides the same outcome.
- **Outcome:** won: the boss sinks (`by: 'finisher'`), bonus loot, the battle goes on; failed: the boss gets 15% of its hull back and the battle goes on.
- **On screen** (`finisher/scene.js`): letterbox bars, the island dimmed and grey with the boss left in colour, the camera pushed in on it, the sea in slow motion, the title card "Bring her down!", the task with mouse, keyboard and touch controls, the crew's progress and each captain's score, the result card, and the narrator's line as a caption that always shows. Reduced motion: no slide-ins, no slow motion, no shake.

## 5. Towers with skill trees, the Tech hub (lane P)

Each tower kind gets a small skill tree beyond its levels (1–3, and 4–5 since the tower tiers of §4.1), chosen per building (like a specialisation), researched once at the Tech hub with coins and then unlocked for every tower of that kind on the island:
- **Cannon:** Rapid (reload −30%) · Heavy shot (damage +60%, slower) · Chain shot (slows ships 40%).
- **Mortar:** Cluster (3 smaller blasts) · Fire pot (burning ground for 4 s) · Long range (+12 range).
- **Wall:** Stone (hp ×2) · Spiked (boarders take damage while hacking) · Quick mend (repairs ×2).
- **Watchtower:** Spotter (+15% damage to towers in range) · Signal fire (ships show 5 s earlier).
New tower kinds later: fire tower (damage over time), for waves 12+. The harpoon tower (slows) is in the game, see "The harpoon tower" below.

### The harpoon tower (lane T1, `feat/v3-t1-harpoon`)

A support tower for waves 12 and up: it hits one ship and slows it, and does little else. It stands on the seven tower spots (`cannon_1`…`cannon_7`), chosen once like a cannon or a mortar, so every harpoon is a cannon not built. Not at Pirate Point.
- **Opens** (`campaign.json`): levels 1 to 3 after wave 12, level 4 after wave 15, level 5 after wave 20; a locked one reads "Opens after wave N" like the others. The build card line: "Slows one ship at a time with a rope harpoon." **Prices** (`islands.json`, same as the watchtower): 🪙 40, 80, 160, 320, 640.
- **In the sim** (`CONFIG.levels.harpoon`, `CONFIG.harpoon`): damage 2, 3, 4, 5, 7 (a cannon does 10 to 38), range 30, 32, 34, 36, 38 (a little more than a cannon's at the same level), reload 2.6, 2.4, 2.2, 2.0, 1.8 s (× the pace of 0.7), slow 25%, 30%, 35%, 40%, 45% for 2.5, 2.5, 3, 3.5, 4 s. It aims only at a ship that is still sailing (one at anchor is not going anywhere) and has no harpoon on its way; a ship that is not slowed yet comes first, then the one nearest its anchorage. Boarders are never a target and never slowed; the flagship is skipped while it is armoured. The throw always hits (no dice), flies at 32 units a second and sends `harpoon_thrown`; the hit sends `ship_hit` (the low damage) and `ship_slowed {slow, until, harpoon: true}`. A second hit **refreshes** the time, it never adds up, and it never weakens a stronger slow already on the ship (Chain shot's 40%). A slowed ship shows `slowed: true` in `state().ships`. A gunner never mans a harpoon and the tower is not a "cannon" for the fog edge. Watchtower range and damage, Eagle eye and War drums reach it like any tower; there are no harpoon skills or research yet.
- **Why it is a support tower:** two harpoons in place of two cannons cannot win a wave the cannons win (`tests/pirates/harpoon.test.js`); the slow is worth most beside cannons, which get more shots at a ship that takes longer to arrive.
- **Art** (`src/art/island.js`, `fleet.js`): a wooden frame with a big crossbow, a harpoon on a rope and a rope coil; iron bands and a stone pad from level 2, brass limbs at 3, gold trim and the island's banner at 4, a gilded crossbow and the starred banner at 5; a firing frame at every level; a barbed harpoon with its rope in flight; a slowed ship gets foam rings on the water and a small rope coil over the hull.

### 5.3 Captain tree and roles (lane T20, `feat/v3-captain-tree`)

The captain's own skill tree (TOWER-DEFENSE §14) is deeper and makes the crew decide who does what. Each of the three branches has **five tiers**; skill points are unchanged (one per two won waves, none spent on coins).

- **Layout of a branch** (Marksman shown; Brawler and Shipwright are the same shape): tier 1 `Steady aim` → **fork** tier 2 `Long barrel` (+3 range) **or** `Hot shot` (+15% damage) → tier 3 `Quick hands` (needs either pick; reload −25%) → **fork** tier 4 `Far sight` (+4 range) **or** `Heavy shot` (+20% damage) → tier 5 capstone `Dead eye` (+30% damage, +2 range), **Gunner only**. A fork is exclusive: the other node closes for that captain (greyed, struck through) until a respec. Costs 1, 2, 3, 3, 4 points a tier; a full branch is 13 points, 26 won waves, a whole captain (all three) 39.
- **Brawler:** `Cutlass` → `Sweep` or `Heavy blade` (strike +25%) → `Second wind` → `Snap shot` (gun reload −15%) or `Bruiser` (strike +30%) → `Field surgeon` (Medic only: helped-up captains stand with full hp). **Shipwright:** `Quick fix` → `Long reach` or `Sturdy planks` (rebuild at 55%) → `Master shipwright` → `Swift hammer` (repairs +25%) or `Wide arc` (reach +2) → `Grand engineer` (Engineer only: rebuild at 80%).
- **Role choice** (once, from **captain level 3**, free): **Medic** opens the Brawler capstone, **Engineer** the Shipwright capstone, **Gunner** the Marksman capstone. Effects: Medic: help-up hold **1.2 s** instead of 2, the captain helped up stands with **75%** hp instead of 50%; Engineer: walls they repair or rebuild get **+25% hp** (once per wall and wave), buildings and upgrades cost **10% less** on islands (rounded to whole coins; Pirate Point stays at list price); Gunner: musket and weapon damage **+20%**, reload **−15%** (the 0.3 s floor still holds).
- **Respec:** `POST /api/island/respec {actionUid}` clears every skill and the role for **🪙 100 × captain level** (300 at level 3, 500 at level 5; wallet reason `captain_respec`, ref `respec:<uid>`; `409 nothing_to_reset`, `409 insufficient_funds`). The points come back by themselves (earned minus learnt).
- **Server:** `POST /api/island/skill` also refuses `409 closed` (the twin was picked) and `409 wrong_role`; `POST /api/island/role {role}` (`400 bad_role`, `409 locked`, `409 role_known`). `GET /api/island` skills carry `role`, `roleLevel`, `roles`, `respecPrice`, and tree nodes `needs` (a list: any one opens it), `excludes`, `role`. `GET /api/games/{code}` members carry `captainRole`.
- **Screens agree:** the role is one more id in the skills list every room message already carries (shot, strike, repair, rebuild, and now `captain_revive`), so the wall hp and the revive hp come out the same on every screen; the help-up hold is the reviver's own timer (their loadout). The lobby (Players and invite) shows each captain's role icon: 🩹 Medic, 🔧 Engineer, 🔫 Gunner.
- **Data:** `backend/content/islands.json` `captainSkills` and `frontend/src/pirates/captain-ids.js` are two copies that `tests/pirates/captain-stats.test.js` compares, with the check rules of `supabase/migrations/20261112120000_captain_tree.sql` (not applied: column `islands.captain_role`, `island_learn_skill()` recreated, `island_pick_role()`, `island_respec()`). Tests: `backend/server/tests/test_captain_tree_routes.py`, `island_sql/test_captain_tree_sql.py`, `frontend/tests/island/captain-tree.test.js`.

## 6. Narration (lane N)

- A **narrator** speaks short lines (one to three sentences) at: the opening (Start), each wave's start for the first 5 waves, every unlock in section 4, the first boss, the first boarding, a player falling and being revived, the heart in danger (below 30%), a lost wave, every 10th wave, the final battle. Captions show the text (always, for sound off and accessibility).
- Lines live in one data file (id, text, trigger); audio is generated with the existing pipeline `scripts/voice/generate.py` and the existing ElevenLabs key (never printed or committed); files are small mp3s loaded on demand. If a file is missing the caption still shows.
- The narrator never blocks play: lines queue, a skip button hides the caption.
- **Built (lane N, `feat/v3-narrator`):** 57 lines in `frontend/src/narrator/lines.json` (voice George, the villain is **Captain Redtide**), the module `frontend/src/narrator/` (one line at a time, stale lines dropped, told once per island game and stored per island code in localStorage, except "welcome back"), a caption card bottom centre with Skip ×, Settings › **Narrator** and **Narrator captions** (both on by default), the voice through the game's audio (Voice volume, music ducked while it speaks). The unlock lines follow the table in section 4 and play from `campaign_unlocked` (lane P, section 4.1).
- **Bus events the other lanes emit for the narrator** (the module header in `src/narrator/index.js` is the reference):

| Event | Fields | Lane | Narrator line |
|---|---|---|---|
| `game_started` | `{code, resumed?, wave?}` | R (host presses Start) | the opening the first time on this island, else welcome back (replaces today's call from `game.js`) |

## 7. Art: clean cartoon 2D (lane A)

- Replace the pixel art with **clean cartoon sprites**: smooth shapes, bold dark outlines, soft two-tone shading, warm saturated colours, in the spirit of mobile strategy games (original designs only, nothing copied from any existing game).
- Drawn as vector art in code (SVG or Canvas 2D paths) and rasterised at runtime to textures at the device's pixel density, so they stay crisp at any size and the download stays small. No image downloads, no new packages.
- Same frame names and anchors as the current atlas where possible, so the renderers keep working; new frames for new things are added in the same module.
- **Captain colours:** each member of a game gets a colour index 0–9 by join order, the host first (`captainColours` in `src/island/lobby.js`), shown as a swatch in the lobby; other captains wear `captain-<index+1>`, your own captain (and your musket and cutlass poses in waves) your own index, so 10 players never share a colour.
- **In waves** captains and boarders draw 1.4× (up to 1.8× at a phone's battle zoom, `src/pirates/character-scale.js`); a damaged hull darkens and a burning one carries its fire and smoke on top, so ships stay readable.
- The camera keeps its angle; the island, water, buildings, towers, walls, ships, boarders, captains (with a few colour variants so 10 players can be told apart), effects (shots, smoke, splashes, fire) and the HUD frame all move to the new style. The HUD kit drops the pixel fonts and borders for clean rounded panels.
